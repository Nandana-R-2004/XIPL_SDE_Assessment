# Q4 - Automated Quality Evaluation of Try-On Results

## Objective

This module evaluates the five virtual try-on outputs generated in Q3 using three complementary quality metrics:

1. Garment fidelity
2. Identity preservation
3. VLM-as-judge quality assessment

The completed evaluation results are stored in `evaluation_template_q4.csv`.

---

## Evaluation Pipeline

For each of the five person-garment pairs, the evaluation pipeline uses:

- Original person image
- Input garment image
- Q3 CatVTON try-on output
- Q3 garment-region mask

Each result is evaluated independently on three axes.

---

## 1. Garment Fidelity

Garment fidelity is measured using OpenCLIP image embeddings.

- Model: ViT-B-32
- Pretrained weights: laion2b_s34b_b79k
- Metric: cosine similarity

The Q3 CatVTON mask is used to isolate the generated garment region from the try-on output.

OpenCLIP embeddings are computed for the original target garment and the generated garment region. The final garment fidelity score is the cosine similarity between the normalized embeddings.

A higher score indicates stronger preservation of the target garment appearance.

---

## 2. Identity Preservation

Identity preservation is evaluated using face-region SSIM (Structural Similarity Index Measure).

An OpenCV Haar Cascade detector identifies the face in the original person image. The same detected face bounding box is then applied to both the original person image and the generated Q3 output.

Using the same spatial region prevents inconsistent face detections between the original and generated images.

Both face regions are resized to 256 x 256 pixels and converted to grayscale before SSIM is calculated.

A score closer to 1 indicates stronger structural preservation of the person's face.

---

## 3. VLM-as-Judge

The same vision-language model used in Q1 is reused for automated quality judging:

- Model: openbmb/MiniCPM-V-2_6-int4
- Quantization: INT4
- Inference: deterministic with sampling disabled

For each pair, the VLM receives three images in this order:

1. Original person
2. Target garment
3. Generated virtual try-on result

The VLM returns an overall quality score from 1 to 10 together with a written reason.

---

## VLM Judge Rubric

The VLM is instructed to evaluate the generated try-on result using the following criteria.

### Fit Realism

Assess whether the target garment fits naturally on the person's body. Check the neckline, shoulders, sleeves, torso, garment boundaries, body pose, and overall geometric plausibility.

### Artifacts

Check for visible generation problems including distorted anatomy, warped arms, broken garment edges, duplicated fabric, unnatural blending, missing regions, incorrect boundaries, and other generation artifacts.

Fewer and less severe artifacts should receive a higher score.

### Texture Transfer

Compare the generated garment with the input target garment. Check whether the garment's color, pattern, print, texture, and important visual details are preserved.

### Scoring Guide

- 1-2: Failed try-on with severe errors or incorrect garment
- 3-4: Poor result with major fit, artifact, or texture problems
- 5-6: Acceptable result with clearly noticeable problems
- 7-8: Good result with realistic transfer and only minor imperfections
- 9: Excellent result with very small defects
- 10: Exceptional, near-perfect virtual try-on

The VLM is instructed to return valid JSON containing:

- `score`: integer from 1 to 10
- `reason`: concise explanation covering fit realism, artifacts, and texture transfer

## Implementation Notes

Evaluation scores are not manually assigned in the evaluation pipeline.

- Garment fidelity is computed from OpenCLIP embeddings.
- Identity preservation is computed using face-region SSIM.
- VLM scores and explanations are generated by the Q1 MiniCPM-V model.
- The official evaluation_template_q4.csv schema is preserved.

---

## Environment and Constraints

Evaluation was performed in Google Colab using an NVIDIA Tesla T4 GPU.

Main libraries:

- PyTorch
- OpenCLIP
- OpenCV
- scikit-image
- Transformers
- bitsandbytes
- pandas
- Pillow

MiniCPM-V-2_6-int4 required bitsandbytes for 4-bit quantization. A Transformers 5.x compatibility issue was encountered with the MiniCPM-V remote model implementation, so Transformers 4.46.3 was used for compatible inference.

The INT4 MiniCPM-V model was used to reduce GPU memory usage on the Tesla T4.
